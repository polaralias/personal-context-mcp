# Core Beliefs

## Belief 1

The product is a context resolver, not an event dump.

## Belief 2

A small service with explicit contracts is better than a feature-rich service with ambiguous behaviour.

## Belief 3

Public docs should describe tested behaviour, not optimistic intent.

## Belief 4

When external integrations fail, the service should degrade clearly and preserve as much safe local utility as possible.

## Belief 5

Refactorability is earned through contract clarity and tests, not through folder restructuring alone.
